## Scope and sources of truth

This repository is a catalogue of pool-bound Uniswap V4 fee hooks for Black Market, plus public authoring contracts and an independent qualification harness. A passing submission is not a security audit or production registry admission.

Read `README.md`, the relevant sections of `CONTRIBUTING.md`, and `SECURITY.md` before changing hook behavior. Treat `CONTRIBUTING.md` as the submission and economics contract; do not invent another schema or payment path.

- `hooks/<slug>/`: concrete hooks, `hook.json`, `integration.json`, and `review.md`. `reference-bound` and `dynamic-fee` are reserved reference examples.
- `contracts/src/`: shared authoring base, optional oracle template, interfaces, and libraries. Contributors must not modify the approved base to make a submission pass.
- `contracts/protocol/`: shipped protocol sources used to deploy fresh V6 infrastructure in qualification.
- `contracts/test/`: Foundry boundary tests and real launch/accounting fixtures.
- `contracts/config/robinhood.json`: pinned historical deployed V5 graph, not newly deployed V6 evidence.
- `scripts/check_hooks.py`, `artifact_checks.py`, `registry_codec.py`: catalogue validation, artifact qualification, and registration encoding.
- `scripts/upstream.json`, `protocol-source-pins.json`, `install-deps.sh`: provenance and pinned dependencies. Keep intentional source changes consistent with their pins; never weaken checks to hide drift.
- `tests/test_submissions.py`: Python runner regressions. `.github/workflows/hooks.yml` defines CI commands and toolchain pins.
- `contracts/lib/`, `out/`, `cache/`, `broadcast/`, `evidence/`, `.integration/`: dependencies or generated/local output, not hand-edited source.

## Required invariants

- Preserve the typed `PoolBoundLaunchHookBaseV2` constructor and one concrete deployed hook. Compose `PoolBoundTruncatedOracleV2` only when a policy needs history; no custom companion deployments.
- Preserve manager-only callbacks, hook mask `0x1afc` under `0x3fff`, one-time registrar binding, and exact full-key checks.
- Keep LP fees zero. Static fees use the creator's maximum; dynamic policies explicitly declare `SwapFeeModel.Dynamic` and remain within the frozen creator-selected minimum/maximum.
- Preserve one rate frozen before each swap, full-precision floor rounding, permanent liquidity custody, backed fee-only liabilities, settlement, and collector-only collection. Donations are not fees.
- Preserve treasury arithmetic: `denominator == 0 ? 0 : (grossHookFee / denominator) * 125 / 100`, with nonzero denominators restricted to `4..10`.
- Match `authorFeeBps()` to `integration.json`. Author payment belongs downstream in the fee hub, using a stable `authorId`; no hook-level payout address, sweep, upgrade, or recipient-selection extension.
- Preserve genuine oracle history and pre-genesis rejection. Capacity is not mature lookback; a swap cannot change its own frozen oracle-based rate.
- Do not change the compiler profile or split deployment to evade artifact limits. Artifact changes require fresh qualification, approved hashes, and newly mined salts.
- Submission pull requests are confined to `hooks/<slug>/`. The shared harness (`contracts/test/`), tooling (`scripts/`), catalogue tests (`tests/`), maintainer docs (`CONTRIBUTING.md`, root `README.md`), and CI workflows are maintainer-owned. If a hook needs new harness capability, that is a separate infrastructure pull request reviewed on its own merits—never bundled into a submission.

## Working and verification

Prefer existing contracts and fixtures over reimplementing accounting or lifecycle logic. Keep changes scoped; preserve unrelated work. Update declarations and review evidence when changing a hook's formula, ABI, dependencies, authority, or economic terms.

Use Python 3.12 and Foundry `nightly-5e88010a83d1b87b8f4d13058e42a2949d3e9dc0`. The pinned compiler is Solidity 0.8.28, Cancun, optimizer runs 1, no via-IR or bytecode metadata. EIP-170 runtime and initcode limits are 24,576 and 49,152 bytes.

Run the relevant checks from the repository root:

```sh
python3.12 -m pip install -r scripts/requirements.txt
python3.12 -m unittest discover -s tests
python3.12 scripts/check_hooks.py --structure-only --output evidence/structure-<unique-run>
scripts/install-deps.sh
forge test --match-path contracts/test/DynamicFeeRate.t.sol -vv
python3.12 scripts/check_hooks.py --output evidence/qualification-<unique-run> --rpc-url https://robinhood.drpc.org
```

Replace `<unique-run>` with a fresh identifier; do not overwrite prior evidence. Structure checks do not compile or qualify a hook. Full qualification checks every catalogue hook, deploys actual V6 actors on a pinned public-chain fork, and exercises the declared fee modes and accounting. Keep chain, fork-block, and deployed-code-hash checks enabled even with a different RPC.

Report commands actually run, failures, missing prerequisites, and evidence paths. Never describe structure-only results, old artifacts, or fixture admission as current full qualification or production approval.

## Security boundary

Treat submissions and CI artifacts as untrusted. Run them in a disposable environment without wallet keys, repository credentials, or sensitive files. Never broadcast during qualification. Do not add secrets, write permissions, `pull_request_target`, or privileged/self-hosted runners to submission CI. Keep FFI disabled. Report vulnerabilities privately through the repository's Security page.
